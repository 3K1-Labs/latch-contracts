# Code of Conduct

## The short version

Be decent to people. Assume good faith. Argue about the code, not the person
who wrote it.

## What we expect

- Give feedback on the work, with a reason. "This breaks the address
  derivation for delegated signers" is useful; "this is terrible" is not.
- Accept feedback the same way. A review comment is not an accusation.
- Respect that people have different amounts of context. Someone new to
  Soroban asking a basic question is doing the right thing.
- Respect that maintainers have limited time. A PR sitting unreviewed is
  usually a queue, not a snub.

## What we won't accept

Harassment, discriminatory language, personal attacks, sustained disruption,
publishing someone's private information, or sexualised language and imagery.

There is one contracts-specific addition. Do not use this project to harm its
users: no deliberately introducing a vulnerability, no disclosing a security
issue publicly before it is fixed (see `SECURITY.md` for how to report one
privately), no phishing contributors or users, and no soliciting anyone's
private keys or recovery phrases for any reason. A maintainer will never ask
for yours, and neither should anyone else.

## Scope

This applies in the repository — issues, pull requests, discussions, code and
commit messages — and anywhere someone is representing the project.

## Reporting

Report conduct issues privately to a maintainer. Reports are handled
confidentially, and whoever receives one will step back if they are involved.

Responses are proportionate: usually a private word, sometimes a warning,
occasionally a temporary or permanent ban. If you think a decision was wrong,
say so; we would rather revisit it than have you leave quietly.
